# Parts of hybrid RAG project-SamRAG
## 1. Tokenization
Raw text cannot be processed directly by neural networks. Tokenizers split text into subword units (e.g., BPE, WordPiece) and map them to discrete integer IDs based on a fixed vocabulary dictionary.
Responsible Project File: ingest/chunker.py
It parses raw PDF manuals (via PyMuPDF), extracts text, and breaks down manual contents into structured, overlapping chunks. It manages chunk token lengths to fit within model context windows and boundaries without truncating critical sentences.

## 2. Input Embedding Space (Dense Vectors)
Integer token IDs are mapped into high-dimensional vector space. Transformer Encoders project semantic context into continuous feature representations where semantically similar texts live close to each other.
Responsible Project File: ingest/embedder.py
It manages calls to embedding Transformer models (gemini-embedding-001). It takes raw text chunks and converts them into dense vector embeddings for indexed storage.

## 3. Vector Storage
Spatial indexing of dense vector outputs generated by Transformer Encoders. It enables fast Cosine Similarity or Dot Product search across large vector spaces.
Responsible Project File: core/storage.py
It defines the contract and handles storage for FAISS dense vector indices alongside SQLite metadata databases to manage offline and online corpus search operations.

## 4. Cross-Encoder Multi-Head Attention (Reranking)
Full joint attention where query and document tokens are concatenated into a single sequence ([CLS] Query [SEP] Document). Every query token directly attends to every document token via Multi-Head Self-Attention layers to compute fine-grained relevance scores.
Responsible Project File: query/rerank.py
It runs candidate chunks through a Cross-Encoder (BAAI/bge-reranker-base) to score and re-rank context relevance before passing it to the generator.

## 5. Context Assembly & Prompt Engineering
Constructing the input payload (Context Window) by merging system instructions, relevant retrieved facts, and user chat history into a structured prompt matrix for the autoregressive Transformer.
Responsible Project Files: query/retrieve.py & core/schema.py
retrieve.py executes BM25 sparse keyword search alongside dense vector lookup to extract top manual chunks. schema.py enforces structured Data Classes and Pydantic types to format retrieved chunks into structured context blocks.

## 6. Autoregressive Decoder, Linear Projection & Softmax Generation
Transformer Core Concept: The Transformer Decoder processes input context through Causal Multi-Head Attention layers. Its Linear Language Model Head projects hidden states to logits matching vocabulary size $V$, and the Softmax function converts logits into next-token probability distributions under sampling settings (Temperature, Top-$p$).
Responsible Project File: query/generate.py
It interfaces with gemini-3.7-flash. It takes assembled prompt contexts, sends generation requests to the LLM Decoder, and controls answer grounding to prevent hallucinations.
## 7. Model Architecture & Hyperparameter Configuration
System-wide initialization parameters defining model names, dimension sizes, temperature settings, and execution backends.
Responsible Project File: core/config.py
It stores global configuration parameters for embedding models, generative LLM choices, API credentials, and reranking flags.
## 8. Application State & User Interface Orchestration
Top-level UI wrapper and event loops that manage stateful multi-turn chat sessions and stream token generations to the user.
Responsible Project File: app.py
The Streamlit user interface entry point. It captures user inputs, triggers retrieval and generation pipelines, handles chat history state, and streams answers back to the UI.

## 1. Tokenization & Subword Processing

* **Transformer Core Concept:** Raw text cannot be processed directly by neural networks. Tokenizers split text into subword units (e.g., BPE, WordPiece) and map them to discrete integer IDs based on a fixed vocabulary dictionary.


* **Responsible Project File:** `ingest/chunker.py`

## 2. Input Embedding Space (Dense Vectors)

* **Transformer Core Concept:** Integer token IDs are mapped into high-dimensional vector space ($\mathbb{R}^d$). Transformer Encoders project semantic context into continuous feature representations where semantically similar texts live close to each other.
